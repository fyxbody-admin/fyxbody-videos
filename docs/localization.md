
## Portal frontend: ES / CA / EN / AR

- Archivos: `wwwroot/portal/messages.js` contiene los cuatro catálogos completos con identificadores semánticos y `descriptions` para traductores. `i18n.js` contiene negociación, renderizado y formato; `app.js` usa `t(id, { argumentos })` en cada punto visible, sin sustitución automática de textos ni `MutationObserver`.
- Los mensajes dinámicos son frases completas. El runtime implementa el subconjunto utilizado de ICU MessageFormat: argumentos con nombre y plurales cardinales anidados con `other`; rechaza sintaxis no soportada y parámetros ausentes. Los plurales árabes incluyen `zero`, `one`, `two`, `few`, `many` y `other`; la selección usa `Intl.PluralRules`. No se presenta este runtime como implementación completa de toda la gramática ICU.
- Las descripciones se conservan aparte del mapa de mensajes de ejecución. No hay integración TMS ni pipeline CI nuevos. Para añadir una clave, completar los cuatro catálogos y su contexto antes de modificar la UI; las pruebas comprueban paridad y parámetros.
- `LocalizedValue` aplaza el formato al idioma activo. Los nodos de texto y atributos se enlazan explícitamente a su mensaje; cambiar idioma actualiza esos enlaces sin remontar la pantalla ni alterar los valores/selecciones. Las fechas, números, porcentajes y listas usan `Intl`. Los instantes usan el huso horario del navegador y calendario gregoriano; los valores ISO de los controles y contratos no se traducen.
- Locale estable: `es`, `ca`, `en`, `ar`. Preferencia válida `localStorage['fyxbody.portal.locale']` → cookie del mismo nombre → idiomas de navegador, admitiendo región → `es`. `locale-preference.js` comparte lectura/escritura y normalización entre el arranque y el runtime; leer nunca sobrescribe una preferencia válida. La elección expresa sincroniza ambos almacenes; se ignoran valores no admitidos. La cookie guarda únicamente el código de idioma, es de host (`Path=/portal/`, `Max-Age=31536000`, `SameSite=Lax`, `Secure` en HTTPS). Si ambos almacenes están bloqueados, funciona el cambio en la pestaña actual y la siguiente carga vuelve a negociar el idioma. Solo árabe activa RTL. `boot.js` resuelve la dirección antes de las hojas de estilo; los estados iniciales y enlace de salto tienen variantes estáticas seleccionadas por `lang`. Sin JavaScript se muestran las instrucciones en los cuatro idiomas.
- Todo fetch y XHR del portal envía `Accept-Language` del idioma vigente al comenzar la solicitud. Los códigos, propiedades JSON y datos fuente mantienen su identidad. Los nombres/títulos usan `dir="auto"`; los parámetros interpolados usan aislamiento Unicode, y los secretos/identificadores técnicos LTR. El cambio de idioma no traduce contenido de clientes ni vídeo/audio. Los mensajes de error humanos ya recibidos del backend mantienen el idioma de aquella respuesta hasta nueva consulta.
- El CSS usa márgenes, rellenos, bordes y posiciones lógicas para los ejes horizontales. La cuadrícula invierte la ubicación de la barra lateral por `dir`; no se reflejan logotipos ni reproductores. Los botones admiten expansión y varias líneas. Los controles nativos de mes/fecha y del reproductor pueden conservar los textos del navegador o sistema operativo; la UI propia, etiquetas y errores de validación se localizan en el portal.
- Fuente árabe: IBM Plex Sans Arabic 400/500/600/700, TTF locales y OFL en `portal/fonts/`. Fuente: Google Fonts CSS API y `google/fonts/ofl/ibmplexsansarabic/OFL.txt`, descargados el 2026-11-05. El runtime no depende de recursos externos. El árabe no aplica mayúsculas ni espaciado entre letras y respeta la formación natural de sus glifos.

### Verificación frontend

`node --test tests/portal-i18n/*.test.mjs` verifica los catálogos completos, descripciones, parámetros, plurales árabes, faltantes, negociación regional y fallback, dirección RTL, formato local, identidad Unicode de datos y presencia de headers en los tres transportes. Incluye expansión pseudo de los nodos literales del AST sin alterar argumentos o categorías. `node --check` valida `app.js`, `i18n.js`, `messages.js`, `boot.js`, `locale-preference.js` y `layout.js`.

La revisión en navegador corresponde al flujo integrado: login y shell en los cuatro idiomas, persistencia tras recarga, formularios/errores/estados vacíos, tablas/paginadores, catálogo con selección sin guardar, cifras árabes, móviles RTL y las acciones de importación/subida/vista previa. No se ha contratado una revisión lingüística humana ni se afirma una certificación de accesibilidad.

El selector de archivo usa botón y estado propios traducidos; el nombre del archivo seleccionado permanece como dato fuente. El cuadro de selección de archivos del sistema operativo mantiene el idioma del sistema.

Backend: véase [backend-localization.md](backend-localization.md) para la negociación HTTP y los errores del servidor.

La regresión de persistencia prueba localStorage bloqueado/ausente/inválido, prioridad de una preferencia válida, cookie malformada, escritura HTTPS/HTTP y degradación cuando tampoco se permiten cookies.
